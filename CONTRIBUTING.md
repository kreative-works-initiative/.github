# Contributing to Kreative Works Initiative

Thank you for your interest in contributing! This guide is the default for every repository in the organization. A repository may add its own `CONTRIBUTING.md` with project-specific details, and that one takes precedence.

By participating, you agree to follow our [Code of Conduct](CODE_OF_CONDUCT.md).

## Ways to contribute

You don't need to write code to help.

- **Report bugs** with clear steps to reproduce them.
- **Suggest ideas** and improvements.
- **Improve documentation**, from typos to full guides.
- **Translate** text and docs.
- **Test** on different systems, hardware and setups, and tell us what you find.
- **Design:** UI, icons, illustrations and branding feedback.
- **Write code:** fix issues, add features, improve performance.

## Before you start

1. Search existing issues and discussions to avoid duplicates.
2. For anything beyond a small fix, open an issue first so we can agree on the approach before you invest time.
3. Check the repository's `README` and `LICENSE`.

## Reporting a bug

Please include:

- What you expected to happen and what actually happened.
- Steps to reproduce.
- Your operating system, version and relevant hardware.
- Logs, screenshots or recordings if they help.

Security issues are the exception: please follow the [Security Policy](SECURITY.md) instead of opening a public issue.

## Submitting changes

1. Fork the repository and create a branch from `main`.
2. Keep changes focused: one topic per pull request.
3. Follow the code style and checks described in the repository.
4. Write or update tests and documentation when relevant.
5. Open a pull request describing what changed and why, and link the related issue.
6. Be open to feedback. Reviews are about the code, never about you.

### Commit messages

We prefer short, descriptive messages. [Conventional Commits](https://www.conventionalcommits.org/) is welcome but not required, for example `fix: handle empty input buffer`.

### Sign-off (DCO) or CLA

By default, our repositories use the [Developer Certificate of Origin](https://developercertificate.org/) (DCO). Add a sign-off to your commits with:

```bash
git commit -s -m "your message"
```

This certifies that you wrote the contribution, or have the right to submit it, under the repository's license.

Some repositories require a **Contributor License Agreement (CLA)** instead of the DCO. When that is the case, the repository's `README` or `CONTRIBUTING` file says so, and you will be guided through signing it the first time you open a pull request.

## Licensing of contributions

Unless a repository states otherwise, contributions are licensed under the same license as the project they are submitted to. Repositories that use a CLA describe any additional terms in the agreement itself.

## Questions?

Open a discussion or an issue in the relevant repository. If you're new to open source, tell us. We're happy to help you get started.
